## 1. 版本定位

这一版不是做一个更复杂的复盘平台，而是先解决作者每天真实使用时最关键的问题：

> 可以在网站上在线记录；系统能接住作者当下的状态，提醒并鼓励作者，给一点正反馈，并把下一步变小。

当前仍以个人私有系统为主。未来可能开放给更多人使用，但多用户、公开注册、复杂权限和商业化能力不进入本版。

## 2. 背景与问题

当前站点已经具备复盘展示能力，也有每日记录、场景总览、项目、内容素材和 Diary 等视图。但核心写入流程仍偏本地化：

- 正式记录依赖本地脚本和 JSON 文件。
- 公开部署站点不能安全在线写入。
- 记录后缺少即时反馈，用户容易写完就结束，无法自然进入下一步。
- AI 能力还没有成为“陪伴、鼓励、拆小行动”的工作流。

作者已经明确：道理都懂，但很多时候做不到。因此系统不能只给理性分析，而要承担“接住情绪、降低启动难度、给正反馈”的角色。

## 3. 产品目标

### 3.1 核心目标

1. 作者能在公开域名登录后直接写记录。
2. 记录默认安全保存到线上数据库，不再依赖本地 JSON 作为主写入路径。
3. 每次记录后，AI 给出温和、鼓励、可行动的反馈。
4. 系统把下一步压缩成一个小到能启动的动作。
5. 首页能提醒作者今天是否记录、下一步该做什么，并给予轻量正反馈。

### 3.2 非目标

本版不做：

- 多用户注册和用户后台。
- 指定人分享、好友可见、团队协作。
- 复杂宠物养成系统。
- 复杂游戏化系统。
- Hermes 接入。
- 付费、订阅、公开社区。
- 邮件、微信、浏览器推送等外部通知。
- 心理诊断、治疗建议或医疗判断。

这些能力进入后续需求池。本版已经落地轻量宠物激励，但不做复杂装扮、任务树、商店等重游戏化能力。

## 4. 目标用户与使用场景

### 4.1 作者本人

作者的四个长期经营场景仍然成立：

- 主业：公寓租赁行业系统后端开发。
- 副业：网站产品出海方向。
- 生活和自我：家庭关系、夫妻、父子、儿女关系，自我状态。
- 内容产出：从工作、副业、生活中沉淀公众号内容。

### 4.2 核心场景

#### 场景 A：随时记一条

作者打开网站，登录后在首页或记录页输入一段想法：

- 可以是工作进展。
- 可以是情绪和碎碎念。
- 可以是副业产品想法。
- 可以是内容选题。
- 可以是不成体系的一句话。

提交后系统保存原文，并返回 AI 反馈。

#### 场景 B：写完后被接住

作者可能焦虑、分心、自责或疲惫。AI 不讲大道理，而是先确认作者的真实状态，再给鼓励和一个小行动。

#### 场景 C：系统提醒今天该收束

作者打开首页时，系统展示：

- 今天是否已经记录。
- 最近一次记录是什么。
- 今天建议先完成的一个小动作。
- 连续记录天数或轻量成长反馈。

#### 场景 D：每日结束做一次收束

作者可以补充当天综合复盘：

- 今天最重要的一件事。
- 今天值得肯定的地方。
- 今天卡住的地方。
- 明天第一步。

## 5. 功能范围

### 5.1 Google 账号登录

#### 目标

让作者可以在 Cloudflare Workers 部署的网站上安全登录，并在登录后获得写入权限。

#### 需求

- 支持使用 Google 账号登录。
- 登录后显示用户头像、昵称或邮箱。
- 当前版本只允许配置的作者邮箱拥有写入权限。
- 未登录用户不能写记录、不能看私密记录、不能触发 AI 建议。
- 未登录用户可以访问公开页面和公开记录。
- 支持退出登录。

#### 验收标准

- 未登录访问写入接口返回 401。
- 非作者 Google 邮箱登录后不能写入，返回 403 或只读身份。
- 作者登录后可以写入记录。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`。

### 5.2 在线记录入口

#### 目标

提供一个低摩擦记录入口，让作者不用回到本地仓库就能开始写。

#### 页面建议

优先在首页首屏放一个快速记录框，也可以保留独立 `#record` 或 `#diary` 页面。

#### 表单字段

必填：

- `content`：原始记录内容。

选填：

- `domain`：`work` / `side_business` / `life` / `content`。
- `type`：`progress` / `thought` / `blocker` / `reflection` / `diary` / `content_seed`。
- `mood`：当前情绪。
- `energy`：1-5 分精力。
- `projects`：关联项目。
- `tags`：标签。
- `visibility`：默认 `private`，本版可支持 `public`，`shared` 仅预留。

#### 交互要求

- 文本框打开即可写，不强迫填写复杂字段。
- 默认用最近一次选择的 `domain`，没有则默认 `life` 或空。
- 提交按钮明确显示保存状态。
- 保存成功后立即展示保存成功状态，并显示 AI 生成中。
- AI 建议异步生成，前端轮询回填。
- AI 失败时，记录仍然保存成功，并提示稍后重试生成建议。

#### 验收标准

- 作者能在 30 秒内提交一条记录。
- 表单最小只需要填写一段文字。
- 保存后 D1 中产生一条 `records` 数据。
- 页面不刷新也能看到新记录。

### 5.3 AI 陪伴与行动建议

#### 目标

每条记录保存后，AI 生成一段温和反馈，帮助作者理解状态、获得肯定，并启动下一步。

#### 输出结构

AI 建议必须输出结构化 JSON：

```json
{
  "summary": "我听到的是...",
  "validation": "值得肯定的是...",
  "emotionalRead": "你现在可能有一点...",
  "possibleNeed": "这背后可能是在需要...",
  "nextSmallStep": "现在只做这一步...",
  "gentleReminder": "温和提醒...",
  "encouragement": "一句具体的鼓励",
  "suggestedTags": ["标签1"],
  "suggestedFollowUps": [
    {
      "text": "一个可执行行动",
      "size": "small"
    }
  ]
}
```

#### 语气原则

AI 必须：

- 先接住，再建议。
- 鼓励为主，但不空泛夸张。
- 不说教，不输出“你应该懂”的道理。
- 把建议压缩成一个很小的下一步。
- 区分事实和推测。
- 不做心理诊断。
- 不使用病理化标签。
- 不把私人内容默认转成公开内容。

#### 示例风格

推荐：

> 我听到的是，你其实知道主线是什么，但今天启动它有点费力。值得肯定的是，你没有逃开这个问题，而是把它写下来了。现在不用解决全部，只做一步：打开项目，把第一个要处理的文件名写下来。

避免：

> 你需要提高自律，建立目标管理体系，坚持执行即可。

#### 验收标准

- 每条新记录都尝试生成 AI 建议。
- AI 输出能被前端稳定解析。
- AI 失败不影响原始记录保存。
- AI 建议中必须包含 `nextSmallStep`。
- 情绪低落类内容不能返回过多任务。

### 5.4 首页提醒与正反馈

#### 目标

让首页从“看数据”变成“今天我该开始做什么”的入口。

#### 页面模块

- 今日状态：今天是否已记录。
- 最近一次记录：展示时间、场景和摘要。
- 下一小步：来自最近 AI 建议或未完成行动。
- 轻量正反馈：连续记录天数、累计记录数、本周记录次数。
- 今日收束入口：引导作者写今日综合复盘。

#### 交互要求

- 不制造焦虑，不用惩罚式文案。
- 断更时强调“从今天恢复就好”。
- 连续记录时给具体正反馈，例如“你已经连续 4 天给自己留了复盘时间”。

#### 验收标准

- 首页能显示今日是否已记录。
- 有记录时展示最近 AI 建议中的下一步。
- 无记录时给出低压力开场提示。
- 连续记录天数和累计记录数计算正确。

### 5.5 每日综合收束

#### 目标

保留 Daily Review 的价值，把当天碎片记录收束成一条每日复盘。

#### 字段

- `date`
- `mostImportantThing`
- `wins`
- `blockers`
- `reflection`
- `tomorrowFirstStep`
- `mood`
- `energy`

#### 验收标准

- 作者可以创建或更新当天 Daily Review。
- 首页优先展示当天 `tomorrowFirstStep` 或最近 AI 的 `nextSmallStep`。
- Daily 视图能展示线上写入的记录和每日收束。

## 6. 权限与可见性

### 6.1 角色

本版只实现两个角色：

- `owner`：作者本人，可写、可读全部、可触发 AI。
- `visitor`：未登录或非作者，只能看公开内容。

### 6.2 可见性

- `private`：只有 owner 可见，默认值。
- `public`：游客可见。
- `shared`：预留字段，本版不实现指定人分享。

### 6.3 行为规则

- 新记录默认 `private`。
- 公开必须由作者主动选择。
- AI 建议继承原记录可见性。
- 游客不能通过 API 获取 private 记录。

## 7. 数据迁移与兼容

### 7.1 主数据源变化

本版开始，线上主数据源从仓库 JSON 切换为 Cloudflare D1。

JSON 的新定位：

- 历史数据来源。
- 本地开发种子。
- 导出备份格式。
- 静态回退数据。

### 7.2 迁移要求

- 提供一次性导入脚本，把 `data/records/daily/` 迁移到 D1。
- Diary JSON 默认不导入公开环境，除非作者显式确认。
- 导入时保留原始 `id`、`createdAt`、`domain`、`type`、`visibility`。
- 导入脚本应可重复运行，不产生重复数据。

## 8. 成功指标

### 8.1 使用指标

- 作者能在 30 秒内完成一条记录。
- 记录后 5 秒内看到保存成功状态。
- AI 成功时，建议会异步回填到记录卡片。
- 7 天内至少有 5 天完成在线记录。
- 首页能稳定给出一个下一小步。

### 8.2 质量指标

- 未登录用户无法写入。
- private 记录不会出现在游客 API 或页面里。
- AI 建议不出现诊断性结论。
- AI 建议不超过 3 个行动点，优先 1 个。
