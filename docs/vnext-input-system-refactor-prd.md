# vNext PRD: 输入体系改造

状态：已按收窄范围实现
日期：2026-07-02
产品定位：人生经营站 / 个人经营复盘系统
版本主题：场景、类型、标签三层输入体系

## 1. 版本一句话

把记录入口从“能写东西”升级为“用户知道该怎么写、系统知道该怎么读、AI 知道该怎么增强”的输入体系。

本版不新增复杂分析功能，只做 AI 标签补全，重点解决一件事：

> 让用户在记录时用最低判断成本，把真实输入稳定沉淀成可分析、可闭环、可复用的数据。

## 2. 背景

当前系统已经具备在线记录、AI 建议、未闭环事项、项目、内容素材、日/周/月/年复盘等能力。但随着功能变多，用户在输入前会遇到新的困惑：

- 这条记录应该放在哪个模块？
- 这是日记、任务、笔记，还是复盘？
- 内容素材要不要我自己判断？
- 健康记录应该算生活，还是能影响工作？
- 标签到底应该手动填，还是交给 AI？

因此，系统需要先把“怎么输入”这件事讲清楚，而不是继续增加更多功能。

## 3. 产品目标

### 3.1 核心目标

1. 建立稳定的三层输入体系：场景、类型、标签。
2. 让小白用户能在 30 秒内理解如何记录。
3. 降低输入时的判断成本，不让用户承担分析工作。
4. 让不同类型的记录具备明确边界，减少误选。
5. 为后续 AI 分析、内容提取、任务闭环、趋势统计提供更规范的数据基础。

### 3.2 非目标

本版不做：

- 新增复杂分析报表。
- 新增健康趋势图。
- 新增内容自动生成工作流。
- 新增外部提醒。
- 新增多用户或权限系统。
- 改造周/月/年复盘算法。
- 新增复杂场景经营分析。
- 新增复杂周期趋势分析。

这些能力属于“怎么分析”的后续迭代。本版只聚焦“怎么输入”。

## 4. 核心原则

### 4.1 输入三层结构

每条记录按三层理解：

```text
场景：这条记录属于哪块人生经营领域
类型：这条记录是什么性质的输入
标签：这条记录具体在讲什么、影响什么、后续怎么复用
```

一句话：

```text
场景定归属，类型定读法，标签定连接。
```

### 4.2 用户和 AI 的分工

用户负责：

- 选择场景。
- 选择类型。
- 可选填写 1-3 个主题标签。
- 写下真实原文。

AI 负责：

- 补充状态标签、对象标签、行动标签、影响标签。
- 判断是否可转内容素材。
- 判断是否需要跟进。
- 判断是否可进入复盘素材。
- 判断是否影响其他场景。

系统负责：

- 保存结构化数据。
- 限制明显不合理的类型选择。
- 把任务、内容候选、复盘候选等数据沉淀到后续闭环链路。

## 5. 第一层：场景

场景保持 4 个，不在本版扩展。

| 场景 | 含义 | 示例 |
| --- | --- | --- |
| 主业 | 工作、效率、能力、职业发展、业务理解 | 接口性能、线上问题、自动化、业务理解 |
| 副业 | 出海产品、产品实验、增长、商业化探索 | 产品定位、竞品、流量、转化、收入 |
| 内容 | 公众号/文章/观点输出相关 | 选题、表达、素材、读者价值 |
| 生活 | 情绪、家庭关系、自我成长、健康、日常状态 | 亲子沟通、夫妻关系、睡眠、运动、感悟 |

场景回答：

> 这条记录主要属于我人生经营里的哪一块？

## 6. 第二层：类型

### 6.1 类型设计

新版输入类型为 7 个：

```text
任务 / 笔记 / 复盘 / 灵感 / 情绪 / 日记 / 健康
```

其中：

- `任务`、`笔记`、`复盘`、`灵感` 是通用类型。
- `情绪` 是半通用类型。
- `日记`、`健康` 是生活场景专属类型。
- `内容素材` 不再作为手动输入类型。

### 6.2 类型适用范围

| 类型 | 类型性质 | 可用场景 | 说明 |
| --- | --- | --- | --- |
| 任务 | 通用 | 主业 / 副业 / 内容 / 生活 | 有一件事要推进，需要闭环 |
| 笔记 | 通用 | 主业 / 副业 / 内容 / 生活 | 信息、观点、观察、知识点 |
| 复盘 | 通用 | 主业 / 副业 / 内容 / 生活 | 对一件事/一天/阶段做总结和改进 |
| 灵感 | 通用 | 主业 / 副业 / 内容 / 生活 | 还没成型的想法、机会、改进点 |
| 情绪 | 半通用 | 主业 / 副业 / 生活，内容可选 | 需要被接住的感受、压力、焦虑、开心等 |
| 日记 | 生活专属 | 生活 | 生活流、当天片段、碎碎念 |
| 健康 | 生活专属 | 生活 | 睡眠、饮食、运动、身体状态、精力等 |

### 6.3 场景与类型联动规则

选择场景后，类型选项应动态变化。

| 场景 | 可选类型 |
| --- | --- |
| 主业 | 任务、笔记、复盘、灵感、情绪 |
| 副业 | 任务、笔记、复盘、灵感、情绪 |
| 内容 | 任务、笔记、复盘、灵感、情绪 |
| 生活 | 任务、笔记、复盘、灵感、情绪、日记、健康 |

规则：

- 健康只允许在生活场景下选择。
- 日记只允许在生活场景下选择。
- 内容素材不允许手动选择，由 AI 分析后产生。
- 如果用户切换场景导致当前类型不可用，系统自动切到该场景下的默认类型。

### 6.4 日记和复盘的区别

核心区别：

```text
日记 = 记录发生了什么
复盘 = 理解这件事意味着什么
```

| 类型 | 关注点 | 示例 |
| --- | --- | --- |
| 日记 | 发生了什么，我当时怎样 | 今天跟孩子因为作业吵了一下，我有点急。 |
| 复盘 | 我学到了什么，下次怎么做 | 这次沟通的问题是我太快进入纠正模式，下次先听孩子说困难在哪里。 |

### 6.5 内容素材的处理

内容素材不作为手动输入类型。

原因：

- 用户在输入当下不一定知道这条内容是否值得输出。
- 很多可输出内容来自情绪、复盘、灵感、笔记甚至健康记录。
- 内容素材更适合由 AI 作为分析结果识别出来。

AI 后续需要判断：

- 是否可转内容素材。
- 可写成什么选题。
- 适合什么角度。
- 面向什么读者。
- 是否进入内容素材池。

## 7. 第三层：标签

### 7.1 标签定位

标签不是新的分类目录，而是为了让记录未来能被检索、聚合、分析和复用。

标签回答：

> 这条记录具体在讲什么？和谁有关？影响什么？后续怎么处理？

### 7.2 标签类型

标签分 5 类：

| 标签类型 | 作用 | 示例 |
| --- | --- | --- |
| 主题标签 | 这条记录在讲什么 | 睡眠、接口性能、产品定位、亲子沟通 |
| 状态标签 | 当前状态/情绪/能量 | 焦虑、疲惫、卡住、有进展 |
| 对象标签 | 和谁/什么对象有关 | 孩子、妻子、用户、竞品、某个项目 |
| 行动标签 | 后续怎么处理 | 待跟进、可复盘、可沉淀、需决策 |
| 影响标签 | 影响哪个经营面 | 主业效率、家庭关系、健康、收入、内容产出 |

### 7.3 手动与自动分工

用户手动填写：

- 主题标签。
- 最多 1-3 个。
- 可为空。

AI 自动生成：

- 状态标签。
- 对象标签。
- 行动标签。
- 影响标签。
- 内容候选。
- 复盘候选。
- 跟进候选。

注意：本版 AI 分析只到标签和候选判断为止，不展开场景经营分析、周期分析或策略分析。

### 7.4 标签示例

#### 健康记录

```text
场景：生活
类型：健康
主题标签：睡眠、精力
内容：昨晚睡了 5 小时，今天下午写代码效率很差。
```

AI 可生成：

```text
状态标签：疲惫
影响标签：主业效率
行动标签：待观察
```

#### 产品灵感

```text
场景：副业
类型：灵感
主题标签：产品定位、复盘站
内容：复盘站不只是总结工具，更像人生经营站。
```

AI 可生成：

```text
行动标签：可复盘、可输出
影响标签：产品方向
内容候选：是
```

#### 家庭情绪

```text
场景：生活
类型：情绪
主题标签：亲子沟通
内容：今天跟孩子因为作业沟通得不好，我太急了。
```

AI 可生成：

```text
状态标签：急躁、自责
对象标签：孩子
影响标签：家庭关系
行动标签：下次先倾听
```

## 8. 输入表单设计

### 8.1 最小输入字段

用户每次记录只需要：

```text
1. 选场景
2. 选类型
3. 可选填 1-3 个主题标签
4. 写原始内容
```

### 8.2 字段说明

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 场景 | 必填 | 四大人生经营场景 |
| 类型 | 必填 | 根据场景动态展示可选类型 |
| 主题标签 | 选填 | 用户手动填写，最多 3 个 |
| 原始内容 | 必填 | 自由输入，不要求结构化 |

### 8.3 高级字段

高级字段保持折叠：

- 关联项目。
- 计划时间。
- 情绪。
- 精力。
- 可见性。

规则：

- 任务类展开计划时间和关联项目。
- 健康类可展开健康补充字段。
- 其他类型默认保持轻量。

## 9. 健康类型设计

健康不是第五场景，而是生活场景下的专属输入类型。

### 9.1 健康记录范围

健康类型可以记录：

- 睡眠。
- 饮食。
- 运动。
- 身体不适。
- 精力状态。
- 体重或其他身体指标。

### 9.2 健康记录原则

用户输入时只需要归属生活场景。

如果健康影响主业、副业或内容，不要求用户输入时判断，由 AI 后续识别影响关系。

例如：

```text
场景：生活
类型：健康
内容：昨晚睡眠很差，今天写代码明显没状态。
```

AI 分析：

```text
影响场景：主业
影响因素：睡眠不足
```

## 10. 新手引导

### 10.1 新手理解方式

不向新用户解释复杂模块，只告诉他：

> 你不用会复盘，也不用会整理。你只要会记一笔。

### 10.2 新手记录公式

```text
【发生了什么】
【我现在怎么想/怎么感觉】
【我可能想推进什么】
```

### 10.3 每日最低输入建议

每天最少 3 笔：

1. 一条进展：今天推进了什么？
2. 一条状态：今天真实状态怎么样？
3. 一条下一步：明天最小的一步是什么？

注意：这只是引导，不是强制任务。

## 11. AI 输入后处理

记录保存后，AI 需要基于场景、类型、主题标签和原文做后处理。

### 11.1 AI 需要生成

- 摘要。
- 类型化反馈。
- 状态标签。
- 对象标签。
- 行动标签。
- 影响标签。
- 是否可转内容素材。
- 是否需要进入未闭环事项。
- 是否可作为日/周/月/年复盘素材。

### 11.2 AI 不应该做

- 不应该强行把所有记录变成任务。
- 不应该让用户在情绪记录里感到被催促。
- 不应该把健康记录做医疗诊断。
- 不应该替用户决定所有分流，关键动作仍应可确认或可撤销。

## 12. 验收标准

### 12.1 输入体验

- 用户进入记录入口后，能看到场景、类型、主题标签、原文输入。
- 用户选择不同场景时，类型选项会动态变化。
- 生活场景下才能选择日记和健康。
- 内容素材不再出现在手动类型列表中。
- 用户可以不填标签直接提交。
- 标签最多建议 3 个，超出时系统提示或截断。

### 12.2 数据质量

- 每条记录必须有场景。
- 每条记录必须有类型。
- 用户手动标签只进入主题标签。
- AI 标签需要区分状态、对象、行动、影响。
- 健康记录保存为生活场景下的健康类型。

### 12.3 小白可理解性

- 新用户不需要理解 Daily、Weekly、项目等模块，也能完成记录。
- 新用户能用一句话理解：场景定归属，类型定读法，标签定连接。
- 新用户 30 秒内能写出第一条记录。

## 13. 迭代拆分

### 阶段一：输入表单改造

- 类型从当前版本调整为新版 7 类。
- 内容素材从手动类型中移除。
- 场景与类型联动。
- 用户标签改为主题标签，最多 3 个。

### 阶段二：AI 标签结构化

- AI 输出状态标签、对象标签、行动标签、影响标签。
- AI 判断内容候选、复盘候选、跟进候选。
- 后端保存结构化标签。

### 阶段三：健康输入增强

- 健康类型仅在生活场景可选。
- 健康记录支持轻量结构化补充字段。
- AI 识别健康对主业、副业、生活状态的影响。

### 阶段四：新手引导

- 在记录入口展示极简输入说明。
- 提供每日三笔引导。
- 提供类型选择帮助文案。

## 14. 成功标准

本版成功的标志不是新增了多少功能，而是用户终于能自然理解：

```text
我该怎么记录？
这条记录属于哪里？
它是什么性质？
我需要打什么标签？
哪些判断交给 AI？
```

最终目标：

> 用户负责真实记录，AI 负责识别价值，系统负责沉淀结构。
