# vNext PRD: 记录中枢与 AI 类型化增强

状态：草案待评审
日期：2026-07-02
产品定位：人生经营站 / 个人经营复盘系统
核心用户：站点作者本人

## 1. 版本一句话

把当前系统从“多个模块都能记录”升级为“统一记录中枢 + AI 类型化增强 + 自动经营闭环”。

用户只需要低摩擦记录自己的进展、情绪、任务、想法和复盘，系统负责识别类型、结构化沉淀、给出合适的 AI 反馈，并把需要推进的内容流向任务、项目、内容素材、日复盘和周期复盘。

## 2. 产品定位

本系统不是单纯的复盘站，也不是普通日记、待办、笔记或项目管理工具。

它的定位是：

> 人生经营站：用低摩擦记录留存个人经营数据，再通过 AI 增强分析、情绪陪伴、行动拆解和周期复盘，帮助用户在长期场景中持续闭环和自进化。

核心闭环：

1. 记录发生了什么。
2. 理解它意味着什么。
3. 推动下一步怎么做。
4. 定期回看自己怎么变化。

## 3. 服务场景

系统服务四个长期经营场景。这四个场景既是导航模块，也是所有输入数据的一级标签。

| 场景 | 经营目标 | 典型输入 |
| --- | --- | --- |
| 主业 | 自动化且极致效率，沉淀职业能力和业务理解 | 工作进展、技术问题、效率改进、复盘、风险 |
| 副业 | 出海产品建设探索，验证产品、增长和收益可能 | 产品想法、实验结果、项目推进、竞品观察 |
| 内容 | 筛选后的内容输出，从经历和思考中提炼公众号素材 | 选题、观点、案例、草稿、可输出片段 |
| 生活 | 认知感悟、个人成长、家庭关系、情绪出口 | 日记、情绪、关系反思、亲子/夫妻沟通、生活感悟 |

## 4. 当前问题

当前系统已经具备在线记录、项目、未闭环事项、Daily、Weekly、Monthly、Yearly、宠物激励等能力，但随着功能变多，出现了几个新问题：

- 输入入口分散，用户需要先判断应该去哪个模块写。
- 记录类型不够明确，情绪、任务、笔记、日记、复盘、灵感混在一起。
- AI 建议偏统一，不能根据输入类型切换角色。
- 任务类数据如果没有规范字段，后续闭环和统计会不稳定。
- 首页和各模块展示能力增强了，但用户仍需要理解很多概念。
- 功能增加后，系统需要更强的“引导记录”和“自动分流”，否则容易用不明白。

## 5. 本版目标

### 5.1 核心目标

1. 建立一个统一记录入口，用户不需要先想去哪个模块。
2. 所有输入必须归属四大场景之一。
3. 所有输入必须归属一个记录类型。
4. AI 根据记录类型输出不同的增强结果。
5. 任务类、项目类、内容类输入可以自动或半自动流向对应闭环模块。
6. 首页从“模块聚合”进一步升级为“今日经营驾驶舱”。
7. 保持低摩擦：最小输入仍然只需要一段文字 + 场景 + 类型。

### 5.2 非目标

本版不做：

- 多用户公开注册。
- 团队协作、组织空间、复杂权限后台。
- 复杂游戏化系统、宠物装扮、商店、任务树。
- 外部推送提醒，如微信、邮件、浏览器通知。
- 复杂知识库和全文搜索。
- 将 AI 输出作为心理诊断或医疗建议。
- 重型项目管理能力，如甘特图、工时、多人分配。

## 6. 核心用户路径

### 6.1 随手记一笔

用户打开首页，直接输入一段内容。

最小字段：

- 内容
- 场景：主业 / 副业 / 内容 / 生活
- 类型：情绪 / 任务 / 笔记 / 日记 / 复盘 / 灵感 / 内容素材

系统保存后立即反馈“已保存”，AI 在后台生成增强结果。

### 6.2 AI 接住并增强

系统根据类型切换 AI 角色：

- 情绪类：接住情绪、复述理解、安抚鼓励、给一个很小的行动。
- 任务类：识别目标、状态、风险、计划时间、下一步。
- 笔记类：提炼观点、归纳标签、关联场景。
- 日记类：总结状态、发现模式、给温和建议。
- 复盘类：提炼成果、问题、经验和下一阶段重点。
- 灵感类：判断能否转项目、内容素材或行动。
- 内容素材类：提炼选题、角度、受众、价值和下一步。

### 6.3 自动分流

AI 增强完成后，系统根据用户确认或默认规则把记录流向不同模块：

- 有下一步行动：生成未闭环事项。
- 关联项目：进入项目详情时间线。
- 可输出内容：进入内容素材池。
- 属于每日总结：进入 Daily Review。
- 属于周期总结：进入 Weekly / Monthly / Yearly 草稿。
- 普通记录：保留在最近记录和场景记录中。

### 6.4 今日经营驾驶舱

首页优先回答五个问题：

1. 今天我记录了吗？
2. 今天我状态怎么样？
3. 当前最该推进的一件事是什么？
4. 哪些事情已经超时或卡住？
5. 我最近有什么成果、趋势或值得肯定的变化？

## 7. 信息架构

本版建议收敛为六个主入口：

| 入口 | 作用 |
| --- | --- |
| 首页 | 今日经营驾驶舱，展示状态、下一步、风险、激励 |
| 记录 | 统一记录中枢，承接所有输入 |
| 项目 | 查看和推进主业/副业重点项目 |
| 内容 | 管理可输出内容素材 |
| 复盘 | Daily / Weekly / Monthly / Yearly 复盘 |
| 设置 | 场景、项目、AI、数据和账号设置 |

现有 Diary 不再作为独立核心入口，而是并入“记录”的日记类型和“生活”场景中。可以保留 `#diary` 作为快捷筛选页，但产品语义上归入记录中枢。

## 8. 记录类型定义

### 8.1 类型列表

| 类型 | 说明 | 是否可产生闭环 |
| --- | --- | --- |
| 情绪 | 当下感受、焦虑、烦躁、失落、开心、压力 | 可生成安抚建议和小行动 |
| 任务 | 明确要做的事、待办、推进动作 | 必须进入未闭环事项 |
| 笔记 | 事实、资料、观察、方法、知识点 | 可沉淀标签和关联项目 |
| 日记 | 一天中的状态记录、碎碎念、生活流 | 可进入 Daily 素材 |
| 复盘 | 对某天、某事、某阶段的总结 | 可进入 Daily 或周期复盘 |
| 灵感 | 产品想法、内容想法、改进点 | 可转项目、内容素材或任务 |
| 内容素材 | 明确面向输出的选题、观点、案例 | 进入内容素材池 |

### 8.2 任务类校验

任务类需要更强约束：

- 标题不能为空。
- 场景必填。
- 状态必填，默认 `open`。
- 计划时间可选，但一旦填写必须是合法日期。
- 关联项目只能选择已有项目。
- 任务保存后必须进入未闭环事项。

### 8.3 非任务类校验

非任务类保持轻量：

- 内容不能为空。
- 场景必填。
- 类型必填。
- 项目、标签、计划时间均可选。

## 9. AI 类型化增强

### 9.1 通用输出字段

每条记录的 AI 输出都应包含：

```json
{
  "summary": "简短摘要",
  "contentTags": ["高频内容标签"],
  "suggestedProjects": ["可能关联项目"],
  "nextSmallStep": "下一小步",
  "followupCandidate": true,
  "contentCandidate": false,
  "confidence": 0.82
}
```

### 9.2 情绪类输出

```json
{
  "emotionalRead": "情绪识别",
  "validation": "接住和理解",
  "possibleNeed": "可能的内在需要",
  "gentleAdvice": "温和建议",
  "nextSmallStep": "一个很小的行动",
  "encouragement": "具体鼓励"
}
```

要求：

- 先共情，再建议。
- 不诊断，不吓人，不说教。
- 行动建议必须足够小。

### 9.3 任务类输出

```json
{
  "taskTitle": "任务标题",
  "statusGuess": "open",
  "risk": "可能风险",
  "blocker": "可能卡点",
  "nextSmallStep": "下一步动作",
  "suggestedDueDate": "2026-07-03",
  "suggestedProject": "项目名称"
}
```

要求：

- 明确下一步。
- 识别是否需要跟进。
- 如果用户没写清计划时间，AI 可以建议但不能自动强制写入。

### 9.4 笔记类输出

```json
{
  "keyPoints": ["要点"],
  "insight": "可能的启发",
  "relatedDomains": ["主业"],
  "contentTags": ["标签"],
  "reuseSuggestion": "后续如何复用"
}
```

### 9.5 日记类输出

```json
{
  "todayState": "当天状态",
  "pattern": "可能出现的模式",
  "worthAffirming": "值得肯定的地方",
  "tomorrowFirstStep": "明天第一步"
}
```

### 9.6 复盘类输出

```json
{
  "wins": ["成果"],
  "problems": ["问题"],
  "lessons": ["经验"],
  "nextFocus": "下一阶段重点",
  "reviewDraftCandidate": true
}
```

### 9.7 灵感类输出

```json
{
  "ideaSummary": "想法摘要",
  "potentialValue": "潜在价值",
  "recommendedDestination": "project | content | followup | archive",
  "validationStep": "最小验证动作"
}
```

### 9.8 内容素材类输出

```json
{
  "topic": "选题",
  "angle": "切入角度",
  "audience": "目标读者",
  "value": "读者价值",
  "outline": ["提纲"],
  "nextDraftStep": "下一步"
}
```

## 10. 数据结构调整

### 10.1 records 表建议字段

现有 `records` 继续作为核心主表，建议补强或规范这些字段：

- `domain`：四大场景。
- `type`：记录类型。
- `content`：原始输入。
- `visibility`：`private` / `public` / `shared`，本版主要使用 `private` 和 `public`。
- `mood`：情绪。
- `energy`：精力分。
- `projects`：关联项目数组。
- `tags`：用户或 AI 标签。
- `next_actions`：建议动作。
- `source`：`manual` / `ai_import` / `migration`。
- `structured_payload`：按类型保存扩展结构。
- `ai_status`：`pending` / `completed` / `failed`。

### 10.2 AI 建议表

`ai_suggestions` 建议保留原始 AI 输出，同时增加：

- `record_type`
- `prompt_version`
- `structured_result`
- `destination_suggestions`
- `error_message`

### 10.3 分流关系

建议增加轻量关系表或在相关表里记录 `source_record_id`：

- `followups.source_record_id`
- `content_items.source_record_id`
- `daily_reviews.source_record_ids`
- `period_reviews.source_record_ids`

这样以后可以追踪一条记录如何被转化成行动、内容和复盘。

## 11. 页面设计要求

### 11.1 首页

首页改为“今日经营驾驶舱”，首屏包含：

- 产品定位语句。
- 今日状态摘要。
- 快速记录入口。
- 今日下一步。
- 超时/临近未闭环事项。
- 轻量宠物激励。

首页后续区块顺序建议：

1. 四大场景经营状态。
2. 未闭环事项。
3. 项目主线。
4. 最近记录。
5. 内容素材。
6. 周期趋势。

### 11.2 统一记录页

记录页包含：

- 快速输入框。
- 场景选择。
- 类型选择。
- 可展开高级字段：项目、标签、计划时间、可见性、情绪、精力。
- 保存状态。
- AI 增强结果。
- 分流确认区。

分流确认区示例：

- “加入未闭环事项”
- “关联到项目”
- “转为内容素材”
- “作为今日复盘素材”
- “只保存记录”

### 11.3 场景页

场景页不再只是展示记录，而是回答：

- 这个场景最近在推进什么？
- 哪些事项未闭环？
- 哪些项目有关联？
- 最近情绪和能量如何？
- 有哪些可复用经验或内容素材？

### 11.4 复盘页

Daily 是基石，Weekly / Monthly / Yearly 应基于 Daily 和记录自动生成趋势。

复盘页应分为：

- 自动统计：记录数、闭环率、超时数、内容产出、项目推进。
- AI 总结：趋势、成果、问题、建议。
- 手动复盘：用户确认、补充、修正。
- 历史复盘：查看和编辑已保存周期复盘。

## 12. 交互原则

1. 输入要轻，理解可以重。
2. 先保存，再 AI，AI 失败不影响记录。
3. 能自动判断的让 AI 判断，关键动作需要用户确认。
4. 任务类强校验，情绪和日记类弱校验。
5. 首页只放用户当下最需要知道的内容。
6. 任何 AI 建议都要能转成一个很小的下一步。
7. 系统少讲概念，多用状态和行动引导用户。

## 13. 指标与验收

### 13.1 使用指标

- 每日记录次数。
- 连续记录天数。
- 每周 Daily Review 完成次数。
- 记录转 follow-up 比例。
- follow-up 闭环率。
- 超时事项数量。
- 内容素材新增数量。
- 周期复盘确认次数。

### 13.2 体验验收

- 用户打开首页 10 秒内知道今天该做什么。
- 用户 30 秒内可以完成一条记录。
- 用户不需要理解所有模块，也能通过统一入口使用系统。
- 情绪类记录的 AI 回复不是任务式催促。
- 任务类记录可以稳定进入未闭环事项。
- 内容素材类记录可以稳定进入内容素材池。
- 周/月/年复盘能体现趋势和成果，而不是简单罗列记录。

## 14. 迭代拆分

### 阶段一：统一记录中枢

- 新增或改造统一记录入口。
- 场景和类型必选。
- 高级字段折叠。
- 记录保存后展示 AI 生成状态。

### 阶段二：AI 类型化增强

- 为不同类型建立独立 prompt。
- AI 输出结构化 JSON。
- 前端按类型展示不同反馈卡片。
- AI 结果保存 prompt version。

### 阶段三：自动分流与确认

- 任务类转 follow-up。
- 内容素材类转 content item。
- 项目关联进入项目时间线。
- 日记/复盘类进入 Daily 素材。
- 所有分流动作保留 `source_record_id`。

### 阶段四：首页收敛

- 首页改成今日经营驾驶舱。
- 强化今日状态、下一步、超时事项、场景状态。
- 降低模块说明和静态文案占比。

### 阶段五：周期复盘增强

- Weekly / Monthly / Yearly 明确基于 Daily 和记录趋势生成。
- 增加趋势变化、成果沉淀、风险提醒。
- 周期复盘保留用户手动确认机制。

## 15. 风险与取舍

### 15.1 风险

- 类型过多可能让输入变重。
- AI 自动分流如果过度自信，会产生错误任务或错误内容素材。
- 首页信息过多会重新变乱。
- 情绪类 AI 回复如果太理性，会失去陪伴价值。

### 15.2 取舍

- 类型必须有，但字段要少。
- AI 可以建议分流，但关键写入由用户确认，任务类除外。
- 首页优先展示“今天该怎么经营”，不追求展示全部数据。
- 宠物系统只做正反馈和坚持感，不做复杂玩法。

## 16. 本版成功标准

当用户有任何想法、情绪、任务或进展时，不需要思考“我应该去哪个模块”，只需要打开系统记一笔。

系统能做到：

- 接住情绪。
- 识别任务。
- 沉淀笔记。
- 筛出内容。
- 推进项目。
- 形成日复盘。
- 支撑周/月/年趋势。

最终让用户感受到：

> 我不是在维护一个复杂系统，而是在持续经营自己的人生数据。
