# vNext PRD: 分析体系改造

状态：草案待评审
日期：2026-07-02
产品定位：人生经营站 / 个人经营复盘系统
版本主题：基于输入体系的分析、洞察与闭环

## 1. 版本一句话

在“场景、类型、标签”的输入体系基础上，把系统从“记录后给一句 AI 建议”升级为“持续从记录中提炼状态、模式、趋势、成果和下一步”的分析体系。

分析体系不追求复杂报表，而是回答一个问题：

> 这些记录说明了什么，我下一步该怎么经营？

## 2. 背景

当前系统已经具备：

- 在线记录。
- 场景、类型、主题标签的输入体系。
- AI 补齐状态标签、对象标签、行动标签、影响标签。
- 未闭环事项、项目、内容素材、Daily、Weekly、Monthly、Yearly 等模块。

但当前分析仍存在不足：

- 单条 AI 建议有用，但缺少跨记录的模式发现。
- Daily、Weekly、Monthly、Yearly 仍容易变成记录罗列。
- 场景页还没有稳定回答“这个场景经营得怎么样”。
- 任务闭环、状态、健康、内容候选之间的关系还没有被系统清楚表达。
- 用户需要看到趋势和下一步，而不是只看到数据列表。

## 3. 产品目标

### 3.1 核心目标

1. 基于输入体系沉淀的数据，形成稳定分析层。
2. 让用户看见四大场景的经营状态。
3. 让 Daily 成为每日收束的分析基础。
4. 让 Weekly / Monthly / Yearly 从记录罗列升级为趋势和成果分析。
5. 让 AI 从“建议一句话”升级为“发现模式、提炼判断、推动闭环”。
6. 所有分析最终都要落到一个更小的下一步。

### 3.2 非目标

本版分析体系规划不等于一次性全部开发。

不在首个实现阶段做：

- 复杂 BI 报表。
- 大量图表。
- 医疗健康诊断。
- 财务收益分析。
- 多用户群体分析。
- 外部推送提醒。
- 自动长文生成。

## 4. 分析体系总结构

分析体系分五层：

```text
单条分析：这条记录说明什么？
每日分析：今天我怎么了？
场景分析：这个领域最近经营得怎么样？
周期分析：这一阶段有什么趋势和成果？
行动分析：下一步最该做什么？
```

一句话：

```text
输入负责留存事实，分析负责形成经营判断，行动负责推动闭环。
```

## 5. 第一层：单条记录分析

### 5.1 目标

用户每写一条记录，系统即时给出轻量分析，让用户感觉：

- 被接住。
- 被理解。
- 这条记录已经被系统结构化。
- 下一步变小了。

### 5.2 分析内容

| 输入类型 | 单条分析重点 |
| --- | --- |
| 情绪 | 接住情绪、识别需要、给一个小行动 |
| 任务 | 提炼任务、判断风险、进入未闭环 |
| 笔记 | 提炼要点、生成主题/状态/影响标签 |
| 复盘 | 提炼经验、问题、下一次做法 |
| 灵感 | 判断价值、建议去向 |
| 日记 | 总结状态、发现当天线索 |
| 健康 | 观察睡眠/饮食/运动/精力对状态的影响 |

### 5.3 输出结构

单条分析应输出：

- 摘要。
- 情绪/状态理解。
- 值得肯定的点。
- 下一小步。
- 状态标签。
- 对象标签。
- 行动标签。
- 影响标签。
- 内容候选。
- 跟进候选。
- 复盘候选。

### 5.4 原则

- 情绪类先接住，不催促。
- 任务类必须落到行动。
- 健康类只做状态观察，不做医疗诊断。
- 内容候选由 AI 判断，不要求用户输入时判断。

## 6. 第二层：每日分析

### 6.1 目标

Daily 是整个分析体系的基石。它不是简单日记，而是每天的经营收束。

Daily 要回答：

```text
今天发生了什么？
今天状态怎么样？
今天推进了什么？
今天卡在哪里？
明天第一步是什么？
```

### 6.2 数据来源

- 当天所有 records。
- 当天 daily review 手写内容。
- 当天新增/完成/超时 follow-up。
- 当天健康类型记录。
- 当天内容候选和内容素材。

### 6.3 分析模块

Daily 页面应包含：

| 模块 | 说明 |
| --- | --- |
| 今日事实 | 基于当天记录提炼发生了什么 |
| 今日状态 | 情绪、精力、健康、压力、积极状态 |
| 今日推进 | 主业/副业/内容/生活分别有哪些进展 |
| 今日卡点 | 未闭环、卡住、拖延、反复出现的问题 |
| 明日第一步 | 最小可启动动作 |
| 今日肯定 | 具体正反馈，强化记录习惯 |

### 6.4 用户交互

- AI 可以自动生成 Daily 草稿。
- 用户可以手动修改并确认。
- 用户确认后的 Daily 才作为周/月/年复盘的重要依据。

## 7. 第三层：场景分析

### 7.1 目标

每个场景页不只是记录列表，而是回答：

> 这个场景最近经营得怎么样？

### 7.2 四大场景分析重点

| 场景 | 分析重点 |
| --- | --- |
| 主业 | 效率、能力沉淀、业务理解、自动化、反复卡点 |
| 副业 | 产品方向、验证进展、项目推进、增长实验、商业化线索 |
| 内容 | 内容候选、选题质量、输出节奏、可复用观点 |
| 生活 | 情绪状态、家庭关系、健康、个人成长、能量恢复 |

### 7.3 场景页应回答的问题

每个场景都回答 5 个问题：

```text
1. 最近这个场景发生了什么？
2. 有什么进展？
3. 有什么卡点？
4. 有什么反复出现的模式？
5. 下一步最该推进什么？
```

### 7.4 展示模块

| 模块 | 说明 |
| --- | --- |
| 场景摘要 | AI 总结最近 7/30 天状态 |
| 高频主题 | 高频主题标签和对象标签 |
| 进展与成果 | 已推进、已完成、可沉淀内容 |
| 卡点与风险 | 未闭环、超时、反复状态标签 |
| 影响关系 | 健康/情绪/任务对场景的影响 |
| 下一步建议 | 一个最小行动 |

## 8. 第四层：周期分析

周期分析分为周、月、年。三者不能只是时间跨度不同，而是关注层级不同。

### 8.1 周分析：看节奏

Weekly 要回答：

```text
这一周四个场景的投入是否均衡？
哪些事情闭环了？
哪些事情拖住了？
情绪/健康/效率之间有没有关系？
下周重点是什么？
```

重点：

- 记录节奏。
- 任务闭环。
- 超时事项。
- 场景投入。
- 健康/情绪对推进的影响。
- 下周最小重点。

### 8.2 月分析：看趋势

Monthly 要回答：

```text
这个月主线是什么？
哪些项目真的有推进？
哪些模式反复出现？
哪些内容/能力/关系有沉淀？
下个月经营策略要不要调整？
```

重点：

- 主线判断。
- 项目推进。
- 高频模式。
- 内容沉淀。
- 能力沉淀。
- 关系改善。
- 下月策略。

### 8.3 年分析：看方向

Yearly 要回答：

```text
这一年我在哪些方面变强了？
哪些场景投入产出最高？
哪些长期问题还在重复？
哪些项目/关系/能力值得继续经营？
下一年方向是什么？
```

重点：

- 长期变化。
- 场景投入产出。
- 长期模式。
- 重大成果。
- 重要关系。
- 能力成长。
- 下一年方向。

## 9. 第五层：行动分析

### 9.1 目标

所有分析最终都必须落到行动，否则系统会变成总结机器。

行动分析回答：

```text
当前最重要的一件事是什么？
下一步最小动作是什么？
哪些事应该暂缓？
哪些事需要继续观察？
```

### 9.2 行动输出

每次 Daily / 场景 / 周期分析至少输出：

- 一个当前优先事项。
- 一个 25 分钟内可启动的下一步。
- 一个需要继续观察的模式。
- 一个建议暂缓或放下的事项。

### 9.3 与未闭环事项关系

- 任务类记录可以直接进入 follow-up。
- AI 判断为 followupCandidate 的记录可以提示用户转为 follow-up。
- 周/月复盘中的下一步可以生成新的 follow-up。
- 长期未闭环事项应被场景分析和周期分析显式指出。

## 10. 分析维度

分析体系先保留 6 个核心维度，避免指标过多。

### 10.1 投入分析

看注意力花在哪里。

指标：

- 各场景记录数。
- 各类型记录数。
- Daily 完成次数。
- 哪个场景长期缺记录。

### 10.2 闭环分析

看事情有没有推进。

指标：

- 新增任务数。
- 完成任务数。
- 超时任务数。
- 长期未闭环事项。
- 闭环事项来源场景。

### 10.3 状态分析

看情绪、精力、健康。

指标：

- 高频状态标签。
- 情绪波动。
- 精力趋势。
- 健康记录数量。
- 睡眠/运动/饮食对主业、副业、生活状态的影响。

### 10.4 模式分析

看反复出现的问题。

示例：

- 主业反复出现排查慢。
- 副业反复出现定位不清。
- 生活反复出现沟通急。
- 健康反复出现睡眠不足。
- 内容反复出现有想法但没输出。

### 10.5 产出分析

看沉淀了什么。

指标：

- 内容候选数量。
- 已发布内容数量。
- 可复用经验。
- 项目阶段成果。
- 能力沉淀。
- 关系改善案例。

### 10.6 下一步分析

看下一步应该怎么做。

输出：

- 当前最重要的一件事。
- 最小下一步。
- 建议暂缓事项。
- 需要继续观察的模式。

## 11. AI 角色设计

AI 不应始终是同一种“总结助手”，而应根据分析层级切换角色。

| 分析层级 | AI 角色 |
| --- | --- |
| 单条记录 | 陪伴者 / 整理者 |
| Daily | 收束教练 |
| 场景分析 | 场景经营参谋 |
| Weekly | 节奏教练 |
| Monthly | 经营分析师 |
| Yearly | 人生战略顾问 |
| 内容分析 | 编辑 |
| 任务分析 | 推进教练 |
| 健康分析 | 状态观察员 |

## 12. 页面改造建议

### 12.1 首页

首页应从“模块集合”进一步变为今日经营驾驶舱。

优先展示：

- 今日状态。
- 今日下一步。
- 超时/临近未闭环事项。
- 四场景经营状态。
- 最近值得关注的模式。
- 宠物/激励反馈。

### 12.2 Daily

Daily 应变成每日收束页。

新增或强化：

- AI 今日分析草稿。
- 今日状态。
- 今日推进。
- 今日卡点。
- 明日第一步。
- 用户确认版 Daily。

### 12.3 场景页

场景页应变成经营页，而不是记录列表。

新增或强化：

- 最近 7/30 天场景摘要。
- 高频主题。
- 反复卡点。
- 未闭环事项。
- 下一步建议。

### 12.4 Weekly / Monthly / Yearly

周期页应展示趋势和成果。

新增或强化：

- 投入趋势。
- 闭环趋势。
- 状态趋势。
- 模式变化。
- 成果沉淀。
- 下一周期策略。

## 13. 数据结构建议

### 13.1 单条记录 AI 结果

继续使用 `ai_suggestions.structured_result_json`，建议稳定保存：

```json
{
  "labelGroups": {
    "statusTags": [],
    "objectTags": [],
    "actionTags": [],
    "impactTags": []
  },
  "contentCandidate": false,
  "followupCandidate": false,
  "reviewCandidate": false
}
```

### 13.2 分析快照

建议后续新增 `analysis_snapshots` 表，用于保存 Daily / 场景 / 周 / 月 / 年的 AI 分析结果，避免每次打开页面都重新请求大模型。

建议字段：

- `id`
- `owner_id`
- `scope_type`：`daily` / `domain` / `weekly` / `monthly` / `yearly`
- `scope_key`：日期、场景、周 key、月 key、年 key
- `source_record_ids_json`
- `metrics_json`
- `insights_json`
- `next_actions_json`
- `provider`
- `model`
- `prompt_version`
- `status`
- `created_at`
- `updated_at`

## 14. 迭代拆分

### 阶段一：单条分析标准化

目标：把每条记录的 AI 结果稳定变成可分析数据。

范围：

- 稳定 `labelGroups`。
- 稳定 content/followup/review candidate。
- 前端展示 AI 自动标签。
- 不做复杂跨周期分析。

### 阶段二：Daily 分析草稿

目标：Daily 自动收束当天。

范围：

- 基于当天记录生成 Daily 草稿。
- 展示今日事实、状态、推进、卡点、明日第一步。
- 用户可编辑确认。

### 阶段三：场景经营分析

目标：四个场景页从记录列表升级为经营状态页。

范围：

- 最近 7/30 天场景摘要。
- 高频主题和状态标签。
- 反复卡点。
- 场景下一步建议。

### 阶段四：周期复盘升级

目标：周/月/年从罗列升级为趋势。

范围：

- Weekly 看节奏。
- Monthly 看趋势。
- Yearly 看方向。
- 增加分析快照，减少重复 AI 请求。

### 阶段五：行动闭环增强

目标：让分析自动反哺 follow-up。

范围：

- AI 分析中的下一步可一键转 follow-up。
- 长期未闭环事项进入周期提醒。
- 建议暂缓事项可标记为 deferred。

## 15. 验收标准

### 15.1 单条分析

- 每条 AI 建议都能输出标签组。
- 情绪类记录不会被强行任务化。
- 健康类记录不会输出医疗诊断。
- 内容候选、跟进候选、复盘候选能被保存。

### 15.2 Daily

- Daily 能基于当天记录生成分析草稿。
- 草稿包含今日事实、状态、推进、卡点、明日第一步。
- 用户可以编辑并确认。

### 15.3 场景分析

- 每个场景能看到最近状态摘要。
- 能看到高频主题和反复卡点。
- 能看到未闭环事项和下一步建议。

### 15.4 周期分析

- 周分析能体现节奏和闭环。
- 月分析能体现趋势和主线。
- 年分析能体现方向和长期变化。

## 16. 成功标准

分析体系成功，不是因为页面上有很多图表，而是用户打开系统后能更清楚地知道：

```text
我最近把注意力花在哪里？
哪些事真正推进了？
哪些问题反复出现？
我的状态如何影响行动？
哪些内容和经验值得沉淀？
下一步最小动作是什么？
```

最终目标：

> 输入体系把人生数据留住，分析体系把人生数据变成经营判断。
